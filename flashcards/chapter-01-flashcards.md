## Chapter 1: Infrastructure as Code: Concepts Tested on the Exam — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What does 'idempotent' mean in an IaC context? | Applying the same configuration multiple times produces the same result without unintended side effects. Exam tip: re-running terraform apply with no code changes yields 'No changes. Infrastructure is up-to-date.' |
| 2 | Declarative vs Imperative — which is Terraform? | Declarative — you define the desired end state; Terraform determines the steps to get there. Imperative means specifying exact ordered steps (e.g., shell scripts). Exam tip: Terraform config describes 'what', not 'how'. |
| 3 | What Terraform mechanism enables provider-agnostic, multi-cloud provisioning? | Provider plugins — each provider (aws, azurerm, google, etc.) translates HCL resource blocks into that platform's API calls. Exam tip: one HCL syntax, many providers = multi-cloud/hybrid-cloud enablement. |
| 4 | Which Terraform command detects infrastructure drift without making changes? | terraform plan — compares real infrastructure state to the desired configuration and reports differences. Exam tip: plan = read-only diff, apply = enacts changes. |
| 5 | What is 'click-ops'? | Manually provisioning/configuring infrastructure through a cloud provider's web console instead of code. Exam tip: click-ops causes drift, isn't repeatable, and lacks an audit trail. |
| 6 | Name the 3 core IaC benefits heavily tested on the exam. | 1) Versioning (track/audit changes in VCS) 2) Repeatability/consistency across environments 3) Drift reduction/detection. Exam tip: memorize V-R-D. |
| 7 | How does IaC enable code review for infrastructure changes? | Config lives in a version control system (e.g., Git); changes go through pull requests reviewed by teammates before merge/apply. Exam tip: this is the collaboration benefit distinguishing IaC from console changes. |
| 8 | What happens if a manual change is made outside Terraform to a resource it manages? | Configuration drift occurs — actual state no longer matches the Terraform state/config. terraform plan detects and proposes to reconcile it on the next run. Exam tip: drift detection is a key IaC/Terraform benefit. |
| 9 | Multi-cloud vs Hybrid-cloud — define both in Terraform context. | Multi-cloud = using 2+ public cloud providers (e.g., AWS+Azure) with one tool. Hybrid-cloud = mixing public cloud with on-prem/private infrastructure. Exam tip: Terraform supports both via multiple provider blocks in one configuration. |
| 10 | Give one imperative example and one declarative example of provisioning. | Imperative: a bash script running ordered AWS CLI calls to create then tag an instance. Declarative: a Terraform resource block stating desired instance attributes; Terraform determines the API calls/order. Exam tip: the exam may show a snippet and ask you to classify its style. |
| 11 | Why is 'repeatability' a critical IaC benefit for the exam? | The same configuration reliably creates identical environments (dev/staging/prod), eliminating 'works on my machine' issues. Exam tip: repeatability + consistency = fewer environment-specific bugs. |
| 12 | What problem does version control solve for infrastructure that click-ops does not? | Provides change history, rollback capability, an audit trail, and enables peer review via pull requests. Exam tip: click-ops changes are invisible to version control and hard to audit or revert. |
